# WebDAV-only 最终优化与候选验证 · 2026-10-14

本轮基于两个仓库的最新 `dev/pre-release-performance-20261014`，在独立分支 `release/final-optimized-rc-20261014` 完成开发。没有修改 main，没有创建正式 Release，没有启用自动更新。LAN Lab / LAN 底层没有继续开发。

## 已完成实现

- Windows / Android 的发布者 manifest 增加可选增量索引 `replayCheckpointV1`。正常有新变更时根据已提交水位读取有界尾部，不再列举整个历史目录。
- 每最多 32 个批次形成一个内容寻址的压缩快照；大批次按 8 MiB 原文预算提前分段。它是保留全部原始变更的因果重放检查点，保留父节点、冲突、删除恢复及未知字段，没有把历史扁平化成当前记录。
- 校验包含对象 SHA256、原始批次 SHA256 / 长度、gzip 完整性、解压上限、发布者 / 数据集、连续序列及前后链。写后读取确认完成，才公布指针。
- 缺失、截断、校验错误、路径 / 所有者错误、旧客户端覆盖可选索引等情况回到原来的 JSON 历史。索引写入失败不阻止正常协议发布。支持不接受条件 PUT 的服务，沿用原来的写前检查及写后校验。
- 新设备及长期离线设备下载压缩块与最近尾部，再由现有 Sync Core 重放；旧客户端继续读取原历史。云端原始文件、旧设备目录、outbox、已有身份均未清理或重建。
- Android 捕获只处理尚未完成的变更，outbox 去重使用临时集合；祖先检查改为迭代。持久化格式与冲突算法不变，另用冻结旧引擎做相同输入的语义对照。
- Android 行号分配使用计数索引，保留原来的按顺序分配结果，包括跨类型变化、重复行号及墓碑；与冻结旧投影做 16 组相同输入对照。原实际恢复入口万条运行超过 7 分钟未完成，堆栈定位到原投影的重复遍历和大量分配，不记为 PASS。
- Android 不再为同步摘要复制全部历史；SQLite 大 TEXT 通过有界 UTF-8 流读取。可信备份 UUID 的恢复使用索引匹配，避免逐条重复规范化全部旧记录。
- 五个启动保护点各自独立 gzip 保存，并验证解压后原始 SHA256。旧原文副本仍可读；压缩副本使用不同目录身份，旧程序回退时能创建自己的原文副本。没有减少保护点。
- 不同自动备份在同一秒内不会互相覆盖；完成原文校验及原子写入后才更新记录。相同完整内容可复用，保留十个备份，未知文件不会参与清理。
- 正常恢复保留现有设备身份及正在发布的变更。原有损坏数据库救援路径仍保留原文件及既有恢复策略，未把它冒充保留身份的正常恢复验收。
- APK 使用保守依赖裁剪，保留应用 / Kotlin / Excel 的接口与数据字段，关闭字节码优化与混淆；不增加权限、不裁剪业务数据或安全恢复功能。APK / DEX 增加本候选基准的 2% 回归预算。
- 备份状态显示真实完成记录与实际文件状态；补充空间统计、空间不足 / 写入权限错误提示。SQLite 手动备份不再要求先绑定 Excel。

## 性能证据

各边界分开记录，不能把 JVM 或软件模拟器结果当作真实手机 / 坚果云结果。

| 实测项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 10,000 条记录首次捕获，native SQLite / JVM，相同存储夹具 | 40.504 秒 | 2.873 秒 |
| 10,000 条记录的五个保护点，实际 Linux 文件 | 121,181,740 B | 13,964,455 B |
| 10,000 个历史批次冷恢复 HTTP 请求，Go loopback | 10,002 | 331 |
| 上述 HTTP 响应总量 | 8,895,958 B | 2,719,881 B |
| 上述冷恢复，加明确的 2 ms 每请求延迟 | 43.677 秒 | 8.341 秒 |
| Kotlin 10,000 历史批次，日常一条新变更的响应量 | 1,543,411 B | 3,545 B |
| 上述日常检查 CPU 夹具时间 | 79.349 ms | 3.589 ms |

包含业务投影的万条完整捕获 1.197 秒；纯 Kotlin 引擎万条捕获 0.978 秒、首次重放 0.813 秒；采样 JVM 堆最高 470,569,056 B，包含夹具及两端引擎，测试堆上限 512 MiB。Room 万条 JSON 恢复 9.834 秒，完整数据、身份及私有历史保持一致。当前测量存在同时运行构建的 CPU 竞争，不选择更快的单次结果作为主要对比。

无请求延迟时，Go 冷恢复的压缩 / 完整性校验 CPU 耗时增加（约 1.63 → 2.60 秒）；收益来自减少网络请求和响应量。上面的延迟夹具不是坚果云实测。

## 保留范围与限制

Full Web / Relay / 插件 / Release Runtime 均未修改，包含已批准 Full Web 对照的空差异及 tree SHA。正式站点与更新 manifest 未重新发布。Sync Protocol 1 / Data Contract 1 / Excel Schema 8 / 业务数据库保持不变。

原始云端历史仍按原协议增长；新增加速对象按批次合并，没有声称垃圾回收或常量大小的历史。旧命名空间首次建立索引需要一次完整性回填；旧客户端移除索引、服务不支持加速目录或校验失败时仍可能扫描原历史。新设备仍重放因果历史，不是省略冲突证据的状态覆盖。

较长历史的处理与持久化仍与保留历史总量相关。Go 接收缓存上限 32 MiB，单快照解压上限 16 MiB；这些不等于整个进程内存上限。软件模拟器万条测试及真实设备 RAM / 后台回收验收分开报告。未声称历史可无限增长而保持恒定内存。

LAN v2 保留 Desktop `dev/lan-v2-independent-20261009@948cd4fc9f6ec2d6910fad833c8da60288f85f9a`、Android 同名分支 `b0dd64cb1531502861e16866877db85017094ccf`；LAN Lab 保留 `fix/lan-lab-readiness-20261013@918e1da349dee90c40ca1a0bdd06583f9d406cec` 与 `dev/lan-lab-local-build-20261010@d2483635db00b878e319d6148b4d4648cfd8de83`。

真实用户 Windows / Android 与坚果云、多日离线后的真实联网、后台限制、真实损坏库救援仍为 PENDING。候选供覆盖安装验收，通过后应提升同一组文件，而非重新编译替换已验收文件。
